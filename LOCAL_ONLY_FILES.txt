# LOCAL-ONLY FILES — develop branch only
# =============================================
# These files hold LOCAL-DEV content that must NOT overwrite the production
# branch's copies during a develop → main merge. They differ between branches
# only because local Docker uses an nginx proxy + dev tooling that production
# (docker-compose.prod.yml) never references.
#
# WHY: Local Docker dev needs an nginx proxy (like production) to avoid
# per-component apiUrl() changes. These files set up that proxy.
# With nginx proxy, frontend code uses the SAME relative URLs on both
# branches — no apiUrl() rewrites needed.
#
# HOW TO USE:
#   1. Before any merge/PR to main, run: bash scripts/prepare-merge.sh
#   2. Merge to main, push, deploy
#   3. Switch back to develop, merge main
#   4. Run: bash scripts/apply-local-only.sh
#
# ⚠️ AUTH-CRITICAL FILES MUST NEVER BE LISTED HERE.
# backend/config/settings.py carries the Phase-2 session-auth + CSRF config and
# must reach main unchanged — prepare-merge.sh/check-local-only.sh refuse to
# run if a protected path (see scripts/_local_only_guard.sh) appears below.
#
# FILE FORMAT: one relative path per line. Lines starting with # are comments.
# Empty lines are ignored.

# --- Docker Compose (local dev with nginx proxy) ---
# Production uses docker-compose.prod.yml. This is local dev only.
docker-compose.yml

# --- Nginx dev config ---
# Local nginx proxy that matches production routing:
# /api/* → backend, /* → frontend (with WebSocket for HMR)
nginx/nginx.dev.conf

# Local dev frontend image: dev server + accessible npm mirror.
# Production builds from frontend/Dockerfile.prod instead.
frontend/Dockerfile
